## 2. 差點重犯的誤判（本輪最重要的一節）

PR #1 當初的日誌（`ops/JOURNAL/2026-08-07.md`）額外記錄了一個技術發現：`.github/workflows/audit.yml` 的 H10 檢查（indigenous 內容不得直接進 main）只 `git diff` `content/**`，不涵蓋 `ops/CORPUS/**`，並把它寫進 `BACKLOG.md` B-019。

本輪核對 main 上的 `ops/CORPUS/`，確認現況：**至少 5 個檔案標了 `indigenous: true`，且全部是一般 commit 直接進 main，未走 PR**（例：`2026-08-20-grb-529433-verification.yaml`、`2026-08-22-kavalan-changbin-contemporary-verification.yaml`）。乍看完全印證 B-019 的疑慮，我原本已經要動手把 H10 檢查範圍擴大到 `ops/CORPUS/**`。

**動手前多查了一步，發現這是誤判**：`GOVERNANCE.md` §3 的分級表明確把「新增 CORPUS 條目」列為 **T1（素材）**，權限欄寫「❌ 自動 commit」，與 T3「原民相關內容（無例外）」是分開的兩格；`CHARTER.md` §3 也把「把材料寫進 `ops/CORPUS/`」明列在自主可做、不必問的清單裡。**T3 的「無例外」指的是 `content/` 發布層級，不是 T1 的原始素材蒐集層級。** 若真把 H10 擴大到 CORPUS，會讓過去一個月所有 T1 CORPUS 提交的既定工作流程在 CI 上全部紅燈——這才是真正的風險，而且是我差點親手造成的。

已改為在 `BACKLOG.md` B-019 加註澄清，結案此項，不再視為稽核缺口。

**這件事的意義**：08-07 那個舊 session 寫下 B-019 這筆記錄時，同樣沒有先查 `GOVERNANCE.md` §3 的分級表就下了「這是漏洞」的結論。本輪一開始也差點原樣重複同一個錯誤——**動手修 CI 之前才想到要查權威文件，而不是先查再判斷是不是真的問題**。這比「找到一個 bug」更值得記錄的，是「同一個錯誤模式被觀察到重犯了一次，而且是同一個 agent 的兩次 session」。

## 5. 附記——PR 關閉後，自動化 reviewer 在舊日誌抓到的三個真實錯誤

PR #1 關閉當下，`chatgpt-codex-connector[bot]` 剛好對其送出一輪 review，留了 4 則評論。因為 PR 已因其他理由（內容被 main 取代）關閉，不會再合併，所以不會回頭修那個分支。但其中三則指出 `ops/JOURNAL/2026-08-07.md`（那次舊 session 的日誌）本身確有問題，值得記下來，因為錯誤模式值得注意：

1. **檢索次數對不上，而且比 bot 抓到的更嚴重**：那篇日誌 PRISMA-S 表只有 15 筆 WebSearch＋5 筆 WebFetch，但正文寫「16 次 WebSearch、4 次 WebFetch」——兩者都跟表格對不上。重新核對當時實際執行的工具呼叫紀錄後發現：有 2 次 WebSearch（「回到我的山裡和海邊」、「原視界 噶瑪蘭」）與 2 次 WebFetch（`ioe.sinica.edu.tw`、`research.sinica.edu.tw`——即 bot 指出「F3 提到中研院但表格沒有」的那兩筆）**確實執行了，但完全沒被記進表格**。實際應為 20 次 WebSearch＋7 次 WebFetch，不是日誌寫的任何一個數字。
2. **確信度標錯**：F3 把「WebFetch 本輪對本 session 系統性失效」的**成因**判斷（session/proxy 層限制，非個別網站封鎖）標成 `verified`。但實際查證到的只是「6 個網域都回傳 403」這個現象；「為什麼」是從現象推出的解釋，依 `METHOD.md` §3 只能標 `inferred`。**這正是本專案第一輪日誌 F6 就記錄過的同一種錯誤**（把 CWA key 401 推論出「功能壞掉」時標成 verified）——同一個 agent，一個月後的舊 session 又犯了一次同型錯誤，而且是在寫方法論紀律的同一篇日誌裡犯的。
3. **歷史層／當代層的區分在 METRICS 被壓平**：日誌正文有把兩層分開講清楚，但 `ops/METRICS.md`（該次 PR 版本）的「本輪推翻的先前假設數：2」把這個分層結論簡化成一個扁平數字，讀起來比日誌正文的實際主張更強。

已在 PR #1 留言回覆確認以上三點屬實，不會回頭改那個分支（PR 已關閉），純粹留紀錄供之後參考：**「標了確信度紀律的日誌，不代表寫的時候真的有照著做」**——這件事本身可能比任何單一錯誤更值得記住。
