## 一、原住民族相關內容（最高強度）

台東 16 鄉鎮市住著阿美、排灣、布農、卑南、魯凱、達悟、噶瑪蘭七族。這不是「其中一個主題」，這是台東的基底。做錯的代價不是被糾正，是失去正當性。

### 1.1 法律依據

| 法源 | 內容 | 對本專案的意義 |
|---|---|---|
| 《原住民族基本法》第 21 條 | 於原住民族土地或部落及周邊一定範圍公有土地從事**學術研究**，應諮商並取得原住民族或部落同意或參與，原住民得分享相關利益 | 田野研究需部落同意；**公開資料的再整理不等於田野研究**，但涉及部落特定知識時界線模糊，一律從嚴 |
| 《人體研究法》第 15 條 | 以研究原住民族為目的者，應諮詢、取得各該原住民族之同意；**其研究結果之發表，亦同** | 「發表亦同」是關鍵——不只研究要同意，**publish 也要** |
| 《人體研究諮詢及取得原住民族同意辦法》（原民會＋衛福部，2015-12-31 發布） | 定義「諮商／諮詢」與「同意」的程序 | 「同意」＝在自由且充分知情前提下、經諮商後表示接受（FPIC） |

> 註：本專案目前**不從事人體研究、不做田野訪談**，因此第 15 條尚未直接適用。但一旦開始收口述歷史，立即適用。這一段先寫在這裡，是因為那一天會來。

### 1.2 CARE 原則（原住民族資料治理）

國際上與 FAIR（Findable, Accessible, Interoperable, Reusable）並行的原則。FAIR 講資料好不好用，**CARE 講資料屬於誰**：

- **C**ollective benefit — 產出必須對該族群本身有益，不只對研究者或讀者
- **A**uthority to control — 族群對關於自己的資料有控制權，包含要求下架
- **R**esponsibility — 使用者有責任說明資料如何被使用、被誰使用
- **E**thics — 族群的權利與福祉優先於研究利益

**本專案的具體承諾：任何族人或部落要求修改／下架關於自己族群的內容，一律照辦，不辯論。** 這條要寫在網站的 `/about`。

### 1.3 可執行規則

| # | 規則 | 檢查方式 |
|---|---|---|
| E1 | 內容涉及原住民族（`layer` 含 `people`／`celebration`，或 `tags` 命中族群名／部落名）→ frontmatter 必須有 `indigenous: true` | ✅ 機器 |
| E2 | `indigenous: true` 的內容，**永遠不能由迴圈自動 commit**，一律開 PR | ✅ 機器（CI 擋 main） |
| E3 | `indigenous: true` 的內容必須有 **Local Contexts Notice/Label** 欄位（見 §1.4），不得只用布林同意值 | ✅ 機器 |
| E4 | `consent: declined` 的內容不得建置進網站 | ✅ 機器 |
| E5 | 族語詞彙必須標注來源辭典或發音人，**不得由 AI 翻譯或推測字義** | ✅ 機器（偵測族語欄位需有 `source`） |
| E6 | 祭儀細節、禁忌知識、部落內部事務 → 不收錄 | ⚠️ [人工] |
| E7 | 描述族群時不得使用「原始」「純樸」「消失中的」這類凝視語彙 | ✅ 機器（詞表比對，警告） |

### 1.4 Local Contexts 標籤系統（v1.1 修訂，取代原布林同意）

**原設計的 `consent: pending|obtained|declined` 三態太粗糙。** 文獻回顧（`LITERATURE.md` §1.2）發現 [Local Contexts](https://localcontexts.org/labels/about-the-labels/) 是國際上實際運作的系統，讓**社群自己**定義流通條件。改採其架構：

| 欄位 | 說明 |
|---|---|
| `tk_notice` | **Notice** — 由**機構**在尚未聯繫上社群時先行標記。這正是本專案當前的處境：我們沒有部落授權，但不能因此假裝這些材料沒有歸屬問題。預設值：`open-to-collaborate` |
| `tk_label` | **Label** — 由**社群自己**定義的流通條件。目前一律為 `null`（尚無任何部落參與）。**只有部落可以填這個欄位，本專案的迴圈永遠不得自行填寫。** |
| `bc_notice` | 生物文化相關（作物、海域、傳統領域知識）時適用 |

Local Contexts 的分級可涵蓋：聖物／祭儀材料、性別限制、季節性使用條件、僅供外展用途等——**這些是布林值表達不了的。**

> **關鍵設計意涵：同意不是一個開關，是一組由社群定義的條件。** 系統必須有能力承載「可以看但不能重製」「只有特定季節可展示」這類條件，即使目前還沒有任何一條被填上。**先把欄位留好，是對未來參與者的尊重。**

## 二、真人的話與真人的事

### 2.1 紅線（沿用並強化 `docs/CONTENT-STRATEGY.md`）

以下**絕對不得由 AI 生成**，違反一次信任歸零：

口述歷史、引言、人物故事與描述、統計數據、原住民文化描述、地名／歷史事件／年代、引用來源與參考文獻、照片圖說、田野筆記、音檔逐字稿、社群回答與投稿。

### 2.2 可執行規則

| # | 規則 | 檢查方式 |
|---|---|---|
| E8 | 全形引號 `「」` 包住且長度 > 15 字的段落 → 視為引語，必須有相鄰的 `source` 標注 | ✅ 機器 |
| E9 | 含百分比或「X 年」「X 人」「X 公頃」等量化陳述 → 必須有 `source` 標注 | ✅ 機器 |
| E10 | 出現真實人名（非公眾人物身份執行職務時）→ 需 `consent` 或該人名已在公開來源中以該身份出現 | ⚠️ [人工]，機器只標記 |
| E11 | `voices` 含 `oral-history` 或 `field-note` → 必須有對應的 `audio` 或 `fieldwork` 記錄，否則 fail | ✅ 機器 |

## 三、著作權與授權

**這一節是本專案最容易踩雷、卻最少被想到的地方。**

| # | 規則 | 檢查方式 |
|---|---|---|
| E12 | 每筆 `ops/CORPUS/` 材料必須記 `license` 欄位。不確定 → `license: unknown`，且 `unknown` 不得進入網站內容 | ✅ 機器 |
| E13 | 政府開放資料：確認是否為「政府資料開放授權條款」，並註明版本 | ✅ 機器 |
| **E13a** | **`license: ogdl-1.0` 的來源，其衍生內容必須渲染完整「顯名聲明」** | ✅ 機器 |
| E14 | 照片：**預設不可用**。除非有明確授權（CC / 公眾領域 / 自行拍攝 / 書面同意） | ✅ 機器（無 `license` 的圖片 fail） |
| E15 | 學術論文：只引用與摘述，**不整段轉載**。引用需完整書目 | ⚠️ [人工]，機器檢查書目完整性 |
| E16 | 爬取行為需遵守 `robots.txt` 與合理的請求頻率（每來源 ≥ 2 秒間隔） | ✅ 機器（採集腳本內建） |

**E13a 為法律要件，不是風格偏好。** OGDL v1 明定：使用者**必須**依附錄「顯名聲明」方式標示原始資料提供機關，**未盡此標示義務者「視為自始未取得授權」**。格式：

```
提供機關／單位 [年份] [開放資料名稱及版本編號]
本開放資料依政府資料開放授權條款進行公眾釋出，使用者於遵守本條款各項規定之前提下，得利用之。
政府資料開放授權條款：http://data.gov.tw/?q=principle
```

該條款與 CC BY 4.0 相容。網站需有一個統一的「資料來源與授權」頁承載所有顯名聲明，並由每篇文章連過去。

## 四、AI 揭露

研究倫理現在要求揭露 AI 使用程度。這個專案的特殊性在於——**AI 是主要執行者**。所以揭露不能是一句「本文使用 AI 輔助」，必須逐項。

| # | 規則 | 檢查方式 |
|---|---|---|
| E17 | 每篇內容必須有 `ai_generated: false`（本專案永遠是 false，見紅線），並依 **ICMJE 2024 分位置揭露**拆為兩個欄位（見下） | ✅ 機器 |
| E18 | 兩欄位只能從固定詞彙表取值 | ✅ 機器 |

**v1.1 修訂——依 ICMJE / COPE 分位置揭露**（`LITERATURE.md` §5）：

ICMJE 2024 建議 AI 用於**寫作輔助**寫在 acknowledgment，用於**資料蒐集／分析／圖表產生**寫在 methods。原設計把兩者混在一個陣列，不符規範。改為：

```yaml
ai_in_methods:          # 影響研究結果的——等同 methods 段落
  [來源蒐集, 連結查證, 結構整理, 實體比對]
ai_in_acknowledgment:   # 僅寫作輔助——等同誌謝段落
  [格式轉換, 翻譯初稿, 摘要]
```

**本專案的特殊性必須明說**：ICMJE 的框架預設 AI 是配角，但這裡 AI 是主要執行者。我們的處理是**超出**規範而非規避——三條共識原則（AI 不能是作者／人類承擔全責／必須揭露）在此**加重適用**：`/about` 必須明寫「本站內容由自動化研究迴圈產出，陳昀楷承擔全部責任」。
| E19 | 網站每篇文章底部必須渲染出來源清單與 AI 輔助清單 | ✅ 機器（元件測試） |
| E20 | `/about` 必須說明：本站由自動化研究迴圈維運、人類負責哪些環節、如何回報錯誤與要求下架 | ⚠️ [人工] |

## 六、當規則衝突或無法判斷時

1. **從嚴。** 兩種解釋都合理時，選限制較多的那個。
2. **記錄。** 寫進 `JOURNAL/`，說明衝突在哪、選了哪邊、為什麼。
3. **升級。** 寫進 `BACKLOG.md` 標 `needs-human-ruling`，等人類裁決。
4. **不要停下整輪工作。** 一個項目卡住，做下一個。把卡住的事情記清楚，比枯坐等答案有價值。
