# GOVERNANCE — 審議結構

> 要吸收公共事務的好處（多元觀點、可追溯、程序正義、制度記憶），
> 屏除它的壞處（延宕、責任稀釋、形式主義、不做不錯）。
>
> **這份文件的每一條反病灶規則都對應一篇實證研究，不是憑感覺設計的。** 依據見 §5。

## 0. 為什麼官僚會殺死品質——以及為什麼這裡不會

人類官僚的病灶幾乎全部源於**同一個經濟結構**：

> **審查是稀缺的、序列的、由人執行的。** 每多一關就多等一週；每個審查者都很忙，所以簽名比看內容便宜；每個人都怕擔責，所以不做最安全。

**這個結構在 agent 系統裡不成立。** 審查是充裕的、可平行的、邊際成本接近零。

這個反轉是整份設計的支點。它讓我們可以**要更多觀點而不付延宕的代價**——但前提是必須刻意避開三個仍然存在的陷阱（§2）。

## 0.5 立案關卡：框架挑戰者（v1.1 新增，本文件最重要的一節）

### 這一節怎麼來的

v1.0 設計了六個審議角色。在同一天的實作過程中，人類（陳昀楷）連續提出六次指正：

1. 不要用機器找資料的心態，要用研究者的姿態
2. 是博士生不是碩士生——要有論點，要確信產出有價值
3. 要解決 AI 蒐集資料把不同件事混在一起的偏誤
4. 不要只靠自己想，先去找國內外既有研究與方法論
5. 需要多重角色與層層觀點，但不能因課責而害品質
6. 這件事有沒有先例？雷區與盲點？以及**你對部落小心翼翼是怎麼來的**

**那六個角色，一個都問不出上面任何一題。**

原因是結構性的：**六個角色全部在下游審查「產出是否符合框架」，而上述每一題都在上游質疑「這個框架憑什麼成立」。**

而且順序也錯了——v1.0 是**先寫治理文件、後做文獻回顧**。博士生的順序是反的。順序顛倒，就必然變成「被問一次、補一次」。

### 診斷：兩個結構性缺陷

| 缺陷 | 說明 |
|---|---|
| **D1 全部在下游** | 所有審查都發生在產出之後。沒有任何機制在**動工之前**質疑前提 |
| **D2 順序顛倒** | 先設計、後查證。應該是先例與盲點調查 → 文獻回顧 → 才設計 |

### 角色：`challenger.frame`（「昀楷位置」）

**在每個週期的最開始執行，早於一切工作。** 不審產出，只質疑前提。

固定提問清單（每次都問，不得跳過）：

| # | 問題 |
|---|---|
| Q1 | 這件事**有沒有先例**？查過了嗎？查到的先例是成功還是失敗？ |
| Q2 | 這個做法是**我想出來的**，還是既有方法論？如果是我想出來的，**為什麼既有的不夠用**？ |
| Q3 | 我對某件事**特別謹慎或特別放鬆**——那個傾向**是哪來的**？是推理出來的，還是預設反應？ |
| Q4 | **誰會反對**這個做法？他們的理由會是什麼？ |
| Q5 | 這個設計**會怎麼失敗**？ |
| Q6 | **我沒問的問題是什麼**？ |
| Q7 | 我打算**現在動工**——有什麼是應該**先查完再動工**的？ |

**鐵則：`challenger.frame` 不得自行回答自己的問題。** 它只產生問題；問題必須由實際的檢索去回答，且檢索紀錄要進 JOURNAL。

→ 這條是整個機制的關鍵。一個能自問自答的挑戰者，會直接退化成自我合理化。

### 為什麼這個角色會比人類弱——必須誠實說明

`challenger.frame` **無法取代陳昀楷**，原因有三，且都無法在系統內解決：

1. **同一個底層模型 → 共享同一組盲點。** 它問不出它想不到的問題。
2. **它知道我要做什麼 → 不在框架外。** 人類的有效性有很大一部分來自「沒讀我的文件」。
3. **它沒有利害關係。** 昀楷跟台東有真實關係，這給了他一種模型不可能有的判斷來源。

**但有一件事是可以自動化的，而且正是人類介入中最routine的部分。**

回頭看那六次指正：**其中五次，人類並沒有告訴我答案，只叫我去查。**「去找國內外研究」「有沒有先例」「查一下你為什麼這樣」——這些是**程序性的**，不是實質性的。

**程序性問題能繞過共享盲點**，因為它的合規與否是**可外部觀察**的：JOURNAL 裡有沒有檢索紀錄，是一個事實問題，不是判斷問題。就算 challenger 跟我有同樣的盲點，它仍然可以問「你查了嗎」並檢查有沒有查。

→ **這是分工的正確切法**：
- **自動化**：每次都該問的固定程序性提問（Q1–Q7）
- **保留給人類**：新穎的實質挑戰（例如「你為什麼對部落小心翼翼」——這一題我不認為 challenger 問得出來）

### 修正後的執行順序

```
0. challenger.frame 提出 Q1–Q7            ← 新增，在一切之前
1. 針對 Q1–Q7 實際檢索，紀錄進 JOURNAL     ← 新增
2. 讀 CHARTER / ETHICS / METHOD / ENTITIES / GOVERNANCE
3. ……（原流程）
```

**新設計、新方法、新論點一律適用。** 例行工作（T0/T1）可跳過，但**跳過本身要記錄**——依 §R8，累積的跳過次數要在月度回顧被檢視。

## 1. 角色

**關鍵區分：品質角色與課責角色必須分開。**

把品質審查偽裝成課責程序，是公共事務最深的病灶——結果是兩者都沒做好：品質意見被當成刁難，課責檢查被當成形式。這裡明確切開。

### 1.1 品質層（提升產出，不負責課責）

| 角色 | 只問一個問題 | 權限 | 觸發 |
|---|---|---|---|
| **口試委員（資深）**<br>`reviewer.senior` | 「So what？這個發現跟既有文獻的關係是什麼？是不是在重做別人做過的事？論點站得住嗎？」 | **只能建議，不可 block**。但意見必須進 JOURNAL，且月度回顧要回應 | T2 以上 |
| **指導教授（新進、細心）**<br>`reviewer.detail` | 「每一步做確實了嗎？這個數字哪來的？accessed date？這兩個來源是不是同一份新聞稿？」 | 可 **block-until-fixed**（要求修正，不可否決整件事） | T1 以上 |

> **為什麼資深口委不能 block**：他的價值在於指出方向，不在於守門。給大佬否決權會直接觸發 Tsebelis 效應——一個立場距離最遠的否決者，會把現狀偏誤拉到最大。**讓他罵，但別讓他擋。**

### 1.2 課責層（Koppell 五維，一角色一維，不得兼任）

| 角色 | 課責維度 | 只問一個問題 | 權限 |
|---|---|---|---|
| **研究倫理委員會**<br>`board.ethics` | **liability** 擔責 | 「這會傷到誰？」 | **絕對否決**（全系統唯一），但**必須引用 `ETHICS.md` 具體條號**，不得泛稱「有疑慮」 |
| **教務處**<br>`office.registrar` | **transparency** 透明 | 「格式、schema、來源標示、AI 揭露完整嗎？」 | CI block。**完全機器化**（`audit-content.ts`），不需 agent |
| **學務處／社群窗口**<br>`office.community` | **responsiveness** 回應 | 「一個台東的高中生／一個部落的人看到這頁，會有什麼感覺？會不會覺得自己被當成標本？」 | 可對**社群風險項**block-until-fixed |
| **主計室**<br>`office.budget` | **controllability** 可控 | 「這輪花的 token 與時間合理嗎？有沒有超出授權範圍的行動？」 | **只報告，永不 block**。由 METRICS 自動產生，不需 agent |
| **方法規範** | **responsibility** 守規 | — | 由 `reviewer.detail` 兼（唯一允許的兼任，因為性質同源） |

## 2. 八條反病灶規則

### R1. 平行，不序列
所有角色同時收到同一份材料、同時審。**任何「A 審完才輪到 B」的設計一律禁止。**
→ 官僚延宕百分之百來自序列化。這裡序列化沒有任何好處。

### R2. 異議必須可證偽
「建議再研議」「格局可再提升」「宜審慎評估」——**這些不算異議，等同沒有意見。**

有效異議必須包含三項，缺一不成立：
1. **具體位置**（哪個檔案、哪一行、哪一則 claim）
2. **為什麼是缺陷**（違反哪條規則，或會導致什麼具體錯誤）
3. **修正後應該長什麼樣**

→ 治形式主義與保守偏誤。**提不出修正方向的反對，是情緒不是審查。**

### R3. 預設通過，沉默即棄權
該輪沒提出的異議，**事後不得追認**，只能寫進 BACKLOG 影響下一輪。
→ 治「不做不錯」。人類官僚預設是「未核准即禁止」，那必然導出不作為最安全。這裡反過來。

### R4. 否決權極少、極窄
全系統**只有 `board.ethics` 有絕對否決權**，且必須引用 `ETHICS.md` 條號。其餘角色只有 block-until-fixed——**要求修正，不能殺死。**
→ 依 Tsebelis：否決者數量與彼此距離決定現狀偏誤。要多元觀點，就不能給每個觀點否決權。**觀點要多，否決者要少。**

### R5. 一角色一課責維度
不要求任何角色同時顧全部五維。倫理委員不評論學術價值；口試委員不管格式。
→ 依 Koppell MAD：衝突的課責期待會癱瘓組織。**本位主義在範圍界定正確時是特徵不是缺陷**——你就是要倫理委員在倫理上鑽牛角尖。範圍外的意見自動降為「僅供參考」。

### R6. 匿名化
審查者不知道材料由誰產出、不知道其他審查者說了什麼、不知道前幾輪的結論。
→ 依身份偏誤研究：identity skews debate。**這也順便消滅「向上管理」——沒有上級可以討好。**

### R7. 獨立平行 > 辯論
**不做多輪辯論。** 各自獨立出具意見，機械式彙總。
→ 這條最反直覺，但有實證：多智能體辯論的表現顯著不如**同等次數的獨立取樣多數決**。辯論會讓錯誤答案透過從眾傳染。要更高信心就**增加獨立樣本數**，不是增加辯論回合數。

### R8. 審查者也被審
月度回顧計算每個角色的成績：
- 提出多少異議？其中多少事後證明是真問題？（precision）
- 漏掉多少後來爆掉的問題？（recall）
- 有多少異議因不符 R2 而無效？

持續低效的角色**降級或移除**。
→ 治責任稀釋。人類官僚裡「大家都簽了等於沒人負責」，是因為簽名沒有後果。**這裡簽名有紀錄、有評分。**

## 3. 風險分級決行（依風險，不依階層）

**這是避免「小事也要層層核」的關鍵。** 決行層級由**風險**決定，不由事情的「重要性」或「層級」決定。

| Tier | 內容 | 誰審 | 人類介入 |
|---|---|---|---|
| **T0 例行** | 更新來源狀態、修死鏈、寫 JOURNAL、更新 METRICS | `office.registrar`（機器）| ❌ 自動 |
| **T1 素材** | 新增 CORPUS 條目、`status: seed` 骨架 | registrar + `reviewer.detail` | ❌ 自動 commit |
| **T2 主張** | 新的缺口主張、新結論、修改 COVERAGE 判讀 | + `reviewer.senior` + `office.community` | ❌ 自動 commit，但**列入月報供人類回溯** |
| **T3 高風險** | 原民相關內容（無例外）、引述真人話語、`status: growing` 以上、任何對外 | 全體 + `board.ethics` | ✅ **開 PR，等陳昀楷 merge** |

任何角色都可以**升級**一件事的 tier（T1 → T3），但**不能降級**。升級要寫理由。
→ 這是安全閥：不確定時往上升的成本低，往下降的成本高，所以只開放單向。

## 4. 辯證探究：T2 主張的特別程序

對 T2 的「缺口主張」，**不用魔鬼代言人（找碴），用辯證探究（造反命題）。**

依 Mason (1969) 以降的研究：DI 與 DA 都優於共識決，但**DI 在「浮現隱藏假設」上優於 DA**。缺口主張最需要的正是浮現假設——「我沒找到」與「不存在」之間隔著一整組沒說出口的假設。

**程序**：任何 `confidence: gap` 的主張，必須同時產生反命題並認真尋找支持它的證據。

```
命題 T：長濱鄉噶瑪蘭族的當代生活缺乏中文記載。
反命題 A：記載存在，只是我的檢索方式找不到。

支持 A 的可能證據——必須實際去查，不是列出來就算：
  · 是否用了族語名稱（Kavalan／噶瑪蘭／加禮宛）檢索？
  · 是否查了灰色文獻（GRB 計畫報告、NDLTD 學位論文）？
  · 是否查了日文文獻？
  · 是否被行政區名稱綁住（新社在花蓮豐濱，但社群跨界到長濱）？
  · 是否只查了「噶瑪蘭」而漏了「加禮宛事件」相關脈絡？

結論：查完之後，T 站得住，還是要改寫？
```

**這個程序的副作用比主作用更有價值**：找反證的過程本身就大幅改善了檢索品質。一個經得起反命題的缺口主張，才是真的發現。

## 6. 這個設計會怎麼失敗

誠實列出，作為 R8 月度回顧的檢查項：

1. **R2 被繞過** — 審查者學會寫出「看似具體」但其實空洞的異議（例如逐行挑無關緊要的格式）。偵測：異議的修正採納率若持續趨近 100% 且產出品質無提升，代表在挑安全的小事。
2. **匿名化失效** — 材料本身的文風洩漏來源。偵測：抽查審查者能否猜中。
3. **倫理委員濫用絕對否決** — 引用條號但牽強。偵測：被否決項目的人類覆核推翻率。
4. **T2 自動 commit 累積漂移** — 沒有人類看的中間層，最容易長歪。**這是本設計最大的已知風險**，緩解方式是月報必須逐項列出 T2，而不是只給統計數字。
5. **角色同質化** — 全部由同一個底層模型扮演，觀點其實沒有真正獨立。**這是最根本的限制，無法在本設計內解決**，只能靠 R8 監測與人類抽查。老實說出來，比假裝有多元觀點好。
