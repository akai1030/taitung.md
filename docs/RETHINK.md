# Taitung.md 重新想像：為什麼它很無聊，以及怎麼讓它真的很酷

> 這份文件是對現有專案的誠實診斷與重新構想。不是修補建議，是方向性的重新思考。

---

## 一、誠實的診斷：現在到底怎麼了

### 你說它「不是 wiki」，但它就是 wiki

把所有漂亮的文字拿掉，看骨架：

```
首頁 → 選一個分類（地景層）→ 看文章列表（卡片格線）→ 點進去讀一篇文章
```

這就是維基百科的結構。你只是把「分類」改叫「地景層」，把「條目」改叫「文章」，把介面做得比較漂亮。12 個地景層 = 12 個分類頁。每個分類頁長一模一樣，只是換了顏色。文章頁 = Markdown 渲染 + 側邊欄。

**說「紀錄片風格」，但紀錄片有導演、有剪輯、有觀點。這個網站沒有。它是一個資料庫的前端。**

### 「滾動就是旅程」——其實不是

首頁的滾動體驗：

1. 看到一個大標題
2. 看到季節橫幅
3. 看到 12 個格子（地景層）
4. 看到幾張卡片（最新文章）
5. 看到一句引言
6. 看到地圖預覽
7. 看到投稿邀請

這不是旅程，這是目錄。每一塊都在告訴你「這裡有什麼」，沒有一塊在讓你「感受到什麼」。真正的紀錄片式滾動會讓你忘記自己在滑網頁——你會覺得自己正在走進一個地方。

### 地圖不是主角，是配角

地圖被放在 `/map` 這個獨立頁面，首頁只有一小塊預覽。但你的 CLAUDE.md 說「地圖優先」。實際上，使用者的主要路徑完全不經過地圖——他們從首頁選分類、看列表、讀文章。地圖和內容是兩個平行世界，從來沒有真正交會。

### 五種聲道只是 UI 切換鈕

你設計了學術研究、口述歷史、田野筆記、青年行動、旅人觀察五種聲道。但在實際體驗中，它們只是文章頁上的 tab 切換。使用者不會看到「同一個地方的五種觀點碰撞」，只會看到「這篇文章有兩個版本，切一下」。

聲道應該是同時存在、彼此對話的，不是互斥的 radio button。

### 投稿頁是一張表單，不是邀請

投稿頁列了五種參與方式，每種都有 emoji 和說明文字。但這不是「邀請」，這是「服務台」。

一個 20 歲的台東青年看到這個頁面，心裡想的是：
- 「所以我寫了東西，然後呢？會被誰看到？」
- 「這裡已經有什麼好東西了嗎？我要加入的是什麼水準的東西？」
- 「我的貢獻會消失在資料庫裡嗎？」
- 「為什麼我不直接發 IG？」

零門檻 = 零承諾 = 零動力。

### 視覺很統一，但很單調

色彩系統很美，但所有頁面的「節奏」是一樣的：中等大小的文字、等距的區塊、對稱的版面。沒有大圖打斷節奏、沒有留白製造戲劇感、沒有不對稱的排版製造視覺張力。

12 個地景層的頁面長得一模一樣，只是標題顏色不同。這就像一部紀錄片的每一章都用同一個鏡頭角度。

## 二、根本問題

**你建了一個「關於台東的資訊系統」，但你其實想要的是「一個讓人走進台東的體驗」。**

這兩者的差異：

| 資訊系統 | 體驗 |
|---------|------|
| 組織內容讓人找到 | 設計旅程讓人感受到 |
| 分類 → 列表 → 閱讀 | 沉浸 → 發現 → 共鳴 |
| 使用者目標：查資料 | 使用者目標：被打動 |
| 成功指標：找到想要的 | 成功指標：發現沒想過的 |
| 貢獻 = 提交內容 | 貢獻 = 成為故事的一部分 |

## 三、值得研究的參考案例

以下不是「可以抄的模板」，而是「可以偷的概念」。

### 沉浸式敘事

**NYT Snow Fall / The Pudding / Shorthand**
滾動觸發動畫、影片、地圖變化。使用者不是在「看網頁」，是在「經歷一個故事」。關鍵不是技術，是**編輯決定**——哪個畫面在哪個時刻出現。

→ **可偷的概念**：首頁不是目錄，是一段 5 分鐘的滾動紀錄片。每個區塊不是告訴你「這裡有什麼分類」，而是讓你「看見台東的一個切面」。

### 地圖即介面

**Historypin（historypin.com）**
80,000 位貢獻者在地圖上釘了 400,000 則故事——照片、影片、音檔、文字。可以用 Street View 把歷史照片疊在現在的街景上。地圖不是功能，是整個體驗的入口。

**Maptionnaire**
社區參與式地圖。使用者不只是釘點，還可以畫區域、上傳照片、留語音。地圖是對話的載體，不是資料的視覺化。

→ **可偷的概念**：地圖不是附屬頁面，是主要導航。打開網站就是打開台東的地圖，zoom in 就是走進去。所有內容從地圖上長出來。

### 口述歷史收集

**StoryCorps（storycorps.org）**
全美最大的口述歷史計畫，725,000+ 段錄音。成功關鍵不是技術，是「設計了一個讓人願意說話的情境」——手機 app 提供引導式問題，兩個人面對面錄音，錄完的故事存進美國國會圖書館。

→ **可偷的概念**：不要「投稿表單」，要「錄故事的引導流程」。給使用者 5 個關於台東的問題，讓他們用手機錄 3 分鐘的回答。這比寫一篇文章的門檻低一百倍，但產出的東西更有溫度一百倍。

### 聲音地景

**ECHOES（echoes.xyz）**
GPS 觸發的聲音漫步體驗。走到一個地點，自動播放那個地方的聲音故事。支援空間音效和分支敘事。

**PlugSonic**
歐盟資助的文化遺產聲音平台，可以建立雙耳音效的聲音地景。

→ **可偷的概念**：台東不只有文字和照片，還有**聲音**——海浪、部落歌謠、市場叫賣、火車經過。地圖上的每個點不只有文章，還有那個地方的聲音。打開網站，你先聽到台東，才開始讀台東。

### 社區參與式檔案

**South Asian American Digital Archive（SAADA）**
社區成員不只是「提交內容」，是「共同策展」。他們參與決定什麼值得被收藏、怎麼被呈現、怎麼被詮釋。

→ **可偷的概念**：貢獻者不是「投稿者」，是「共同編輯」。讓在地青年策展自己的專題——「我的台東前五名」「消失中的___」「只有在地人知道的___」。

### 台灣在地案例

**g0v 公民科技社群**
用開源協作解決資訊不對等。成功因素：清楚的貢獻機制、可見的成果、社群認同感。

**台灣文化記憶庫（國家文化記憶庫）**
政府主導的文化數位化計畫，但參與度低——因為它就是一個資料庫。這是**反面教材**：再多的內容，如果體驗無聊，就沒人想參與。

## 四、重新構想：六個方向

### 方向 1：地圖即首頁

**現在**：首頁是一個有很多區塊的長頁面，地圖是其中一小塊。
**重新想像**：打開網站 = 打開台東的全螢幕地圖。

- 地圖上有「脈動」——不同地點會微微發光，表示有內容
- Zoom in 到一個區域，周圍的故事浮現（不是 marker，是文字片段和照片的碎片）
- 點擊任何一個故事，它在地圖上展開，你讀的時候背景就是那個地方的衛星圖
- 12 個地景層是地圖的 filter，不是獨立的分類頁
- 地圖會根據季節改變色調（春天偏綠、夏天偏藍、秋天偏金）

**為什麼這比較不無聊**：使用者的第一個動作是「探索」，不是「選分類」。探索是主動的，選分類是被動的。

### 方向 2：聲音先行

**現在**：文字為主，音檔是附件。
**重新想像**：進入網站的第一件事是聽到台東。

- 首頁有一個環境音層：遠方的海浪、蟲鳴、風聲（使用者可以關掉）
- 每篇文章的開頭不是標題，是 15 秒的「場景音」
- 口述歷史不是「可選的聲道」，而是穿插在文字中的音檔片段——讀到某一段，耳邊響起阿公的聲音
- 地圖上的每個區域有自己的聲音特徵
- 貢獻方式之一：「錄下你身邊的台東聲音，30 秒就好」

**為什麼這比較不無聊**：聲音是最直接的感官體驗。文字要思考才能感受，聲音直接進入情緒。而且「錄 30 秒聲音」比「寫一篇文章」容易太多了。

### 方向 3：對話式聲道，不是切換式

**現在**：五種聲道是文章的不同版本，用 tab 切換。
**重新想像**：同一個頁面上，多種聲音同時存在，像一場圓桌對話。

```
┌─────────────────────────────────────────────┐
│                                             │
│  「都蘭的海岸侵蝕在過去十年加速了 23%，    │
│   主要原因是...」                           │
│                        ── 學術研究，林教授   │
│                                             │
│  ▶ 「我小時候那個沙灘，現在已經不見了。     │
│     我帶孫子去，他問我沙子去哪了。」         │
│                        ── 口述歷史，林阿公   │
│                                             │
│  走在都蘭鼻的步道上，腳下的石頭確實比       │
│  三年前少了。海浪拍打的位置明顯往上移。     │
│                        ── 田野筆記，2025.03  │
│                                             │
│  「我們發起了淨灘 + 海岸監測行動，每個月    │
│   用空拍機記錄海岸線變化。」                │
│                       ── 青年行動，海洋小組   │
│                                             │
└─────────────────────────────────────────────┘
```

四種觀點在同一個頁面上交織，不是互斥的 tab。讀者看到的是一場**對話**，不是四篇獨立的文章。

**為什麼這比較不無聊**：因為張力。學術的冷靜和阿公的感傷並置，就會產生情感衝擊。這是紀錄片的手法——交叉剪輯。

### 方向 4：貢獻 = 回答問題，不是寫文章

**現在**：投稿頁提供五種投稿方式，都需要使用者主動產出完整內容。
**重新想像**：每週一個問題，只要回答就好。

**「這週的問題」機制：**
- 每週由編輯團隊（或社群投票）提出一個關於台東的問題
- 例如：「你在台東最常被蚊子咬的地方是哪裡？」「台東哪裡的星空最美？」「你覺得台東最被低估的食物是什麼？」
- 回答方式：打字（200 字以內）、錄音（3 分鐘以內）、拍照（附一句話）
- 所有回答即時出現在那一週的問題頁面上——你回答完馬上看到自己的答案和別人的
- 每週結束，最好的回答被策展進正式內容

**為什麼這比較不無聊**：
- 門檻極低（回答一個問題 vs 寫一篇文章）
- 即時滿足（答完馬上看到）
- 社交驅動（看別人怎麼回答）
- 有節奏感（每週更新，不是永遠開放的表單）
- 問題本身就是內容（問題的選擇就是編輯觀點）

### 方向 5：不規則的視覺節奏

**現在**：所有頁面都是等距區塊、對稱排版、統一大小的卡片。
**重新想像**：每一頁都像一本獨立的雜誌跨頁。

- 有些區塊是全版面照片，上面只有一句話
- 有些區塊是密集的文字塊，像報紙專欄
- 有些區塊是純粹的留白，只有一個播放按鈕
- 地景層頁面**不要長一樣**——「土地」層用大量地形圖和衛星照片，「人群」層用大量肖像照片，「慶典」層用鮮豔色塊和動態
- 打破格線：不是所有東西都在 12-column grid 裡。讓文字偶爾跑到邊緣，讓圖片偶爾佔滿整個螢幕

**為什麼這比較不無聊**：視覺的不可預測性讓人保持注意力。如果每一頁都長一樣，大腦會進入「掃描模式」——快速掃過，不細看。如果每一頁都不一樣，大腦會進入「探索模式」——停下來，看看這次有什麼。

### 方向 6：時間感

**現在**：文章有 `created` 和 `updated` 日期，但網站沒有時間感。
**重新想像**：網站本身是活的，會隨時間改變。

- **季節不只改 banner**：春天的整個網站色調偏向嫩綠和花色；颱風季網站會有微微的動態（雨滴效果、風的聲音）；冬天色調沉靜
- **「此刻的台東」不是一個區塊，是整個首頁的狀態**：今天如果台東在下雨，首頁的氛圍就是雨天的；如果是豐年祭期間，首頁就充滿慶典元素
- **內容有「新鮮度」視覺**：最近更新的內容在地圖上更亮，很久沒更新的變淡——這讓人知道哪些故事是活的
- **時間軸不只是歷史**：可以拉一個滑桿，從 1624 年拉到現在，地圖上的內容隨年代變化

**為什麼這比較不無聊**：因為每次打開都不一樣。如果一個網站永遠長一樣，你沒有理由回來。如果它是活的，你會想看「今天的台東是什麼樣子」。

## 五、最致命的問題：為什麼有人要參與？

所有上面的設計方向都在解決「體驗」問題，但真正的核心問題是**動機**。

### 現在的參與動機（幾乎為零）

「你的故事是台東的一部分」——這句話很美，但**不是動機**。動機需要三個東西：

1. **我能得到什麼？**（回饋）
2. **我做的東西會被怎麼對待？**（尊重）
3. **我是加入一個什麼樣的群體？**（認同）

現在的網站對這三個問題的回答都是零。

### 重新設計參與動機

**回饋：讓貢獻可見**
- 你錄的聲音出現在地圖上，任何人 zoom in 到那個地點都會聽到
- 你回答的問題被策展進正式內容時，你的名字在那裡
- 每月的「社群報告」——這個月有多少人貢獻了什麼，最受歡迎的故事是哪些
- 實體活動：年度的「台東故事之夜」，把線上內容帶到線下

**尊重：有策展，不是有牆**
- 不是所有投稿都直接上線（那是 wiki），但也不是審稿制（那是期刊）
- 而是：所有投稿都會出現在「社群池」，編輯團隊每週從池裡選出精選內容，放進正式的故事頁面
- 被選中的人會收到一封信：「你的故事被選為本週精選，因為___」
- 沒被選中的內容不會消失，它們留在社群池裡，任何人都看得到

**認同：建立一個有個性的社群**
- 網站要有「態度」——不是中性的知識庫，而是有觀點的。「我們相信台東的故事應該由在台東的人來說」
- 貢獻者頁面不是一排頭像，而是「這些人正在用自己的方式記錄台東」的故事牆
- 讓貢獻者彼此看得到，形成社群感
- 有一個簡單的身份：「我是 Taitung.md 的記錄者」

## 六、如果只能做三件事

如果資源有限，我建議優先做這三件事，效果最大：

### 1. 地圖即首頁（改變入口體驗）
把首頁從「目錄」改成「地圖」。所有內容從地圖上生長出來。這一個改變就能徹底改變使用者的第一印象——從「又一個知識網站」變成「哇，我可以探索台東」。

### 2. 每週一問（改變參與方式）
拿掉投稿表單，改成每週一個問題。極低門檻、即時回饋、社交可見。這會比任何表單都更快地累積社群內容和社群感。

### 3. 聲音層（改變感官體驗）
在地圖和文章中加入聲音——環境音、口述歷史片段、在地聲音。這是成本最低但感受差異最大的改變。一段海浪聲比一千字的海洋描述更能讓人「到達」台東。

## 七、這些改變在技術上意味著什麼

| 方向 | 技術影響 | 難度 |
|------|---------|------|
| 地圖即首頁 | 重寫首頁，MapLibre 全螢幕 + 內容圖層，需要 GeoJSON 資料 | ⭐⭐⭐ |
| 每週一問 | 新的資料模型（問題+回答），需要簡單的後端或用 GitHub Issues/Discussions | ⭐⭐ |
| 聲音層 | Web Audio API，音檔管理，播放器元件 | ⭐⭐ |
| 對話式聲道 | 重新設計文章頁排版，不需要新技術 | ⭐⭐ |
| 不規則視覺 | 每個地景層需要獨立的版面設計，工作量大 | ⭐⭐⭐ |
| 時間感 | 季節引擎強化 + 可能需要外部天氣 API | ⭐⭐ |

## 八、最後的話

Taitung.md 的問題不是技術不好或設計不美。問題是它用「知識庫」的邏輯在做一件需要「體驗設計」邏輯的事。

維基百科的邏輯：**組織所有資訊，讓人找到任何東西。**
紀錄片的邏輯：**選擇最重要的故事，讓人感受到一件事。**

現在的 Taitung.md 在說紀錄片的語言，做維基百科的事。

這意味著：更少的頁面，更深的體驗。更少的分類，更多的敘事。更少的表單，更多的對話。
